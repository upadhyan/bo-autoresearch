## What to build
Warm start across changes, and epochs:
- Mapping rules:
  - an added lever is backfilled at its baseline;
  - a lever removed as credibly irrelevant (rejected `irrelevant`, or frozen) has its key dropped;
  - any other removed lever (`no-improvement`, parked or masked) is filtered to its baseline;
  - narrowing drops out-of-range trials and never clips;
  - merges use their declared value mapping.
- The `narrow` action, which needs its gates to pass and ends the round.
- `commit-change(reason)` and `add-dependency` (into the run venv only, committing the updated lock or freeze file).
- The equivalence check after every code change: the incumbent and the baseline, 2 replicates each, within 2σ. A failure starts a new epoch, earlier trials become telemetry, σ is re-estimated and burn-in restarts.
- User-declared breaking changes skip the check and start a new epoch.

## Acceptance criteria
- [ ] Adding a lever keeps prior trials eligible, backfilled at the baseline.
- [ ] Each removal reason applies its own rule, verified by the eligible trial set.
- [ ] Narrowing drops out-of-range trials, and no clipped values ever appear.
- [ ] A merge with a declared mapping keeps the trials that map. Trials the mapping can't express become ineligible.
- [ ] A change to the toy's objective fails the equivalence check and starts a new epoch. A true no-op change passes.
- [ ] `add-dependency` installs only into the run venv, and the user's environment is unchanged.
