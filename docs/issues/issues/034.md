## What to build
Deterministic enforcement at the agent boundary:
- Harness checks:
  - `check write <path> --agent`: protected paths, the worktree during a round, and the user's checkout outside the run worktrees (with the pre-init `run.yaml` draft as the exception);
  - `check bash <cmd> --agent`: the read-only-agent allowlist, installs made outside `add-dependency`, obvious shell writes to protected paths, history-changing git commands in worktrees, and the orchestrator reading raw logs;
  - `check read`: the orchestrator reading artifacts or `log.db`;
  - `check stop`: allowed when there's no run, when waiting on the user, during a background `round-run`, or after the run has ended and wrap-up has finished.
- Standard-library hook adapters and `hooks.json`:
  - SessionStart, which injects status;
  - PreToolUse on Edit, Write, NotebookEdit, Bash, Read, Grep and Glob;
  - SubagentStop, plus the handback in auto mode;
  - Stop;
  - PostToolUse, which re-injects `next`.
- Adapters are inert when no run is active, fail closed (exit 2) if a check crashes, and every block is logged as `hook_blocked`.

## Acceptance criteria
- [ ] Each check returns allow or block with a reason for a table of cases covering every rule above.
- [ ] Every block is logged.
- [ ] The adapters map allow to exit 0 and block to exit 2 with the reason. With no active run they exit 0 immediately. A crashing check gives exit 2.
- [ ] `check stop` blocks mid-run, and allows during a pending checkpoint and a background round.
