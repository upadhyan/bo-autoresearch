## Question

How are prior **trials** mapped into a new **round's** search space?

Cover these cases: a lever is added (old trials take its "off" value?), removed (drop the trials, or fix it at the incumbent or marginalize?), narrowed (old trials outside the bounds?), and the code under the objective changes, which means old trials measured a different function.

From 2608.00316, consider keeping one raw trial log as the single source of truth and deriving each round's study from it instead of migrating studies, with "fix lever at value" as the way to express "off". Also decide how round 1 is seeded from the user's priors.

## Resolution

**Gist:** the **experiment log** is the only source of truth. Each round's Optuna study is thrown away afterwards and re-derived from the log by one **eligibility function**, which feeds both the sampler's seeds and the verdict GP.

A logged trial is eligible if it is in the current **epoch**, at the round's fidelity, and inside every lever's current range. A lever that was added is backfilled with its **baseline** value, which must reproduce the code's earlier behaviour exactly. A lever that leaves the search space is dropped from trials or filtered on, depending on why it left.

An equivalence check after every code change decides whether a new epoch starts. Round 1 is seeded with the baseline replicates plus a few configs named by the user.

### Source of truth
1. **The experiment log is append-only.** The harness builds each round's study by filtering and rewriting logged trials with `create_trial`/`add_trials`, bounds-checking every one itself. The per-round SQLite studies are disposable.
2. **One eligibility function** chooses the trials for both the sampler's warm start and the verdict GP, so search and verdicts always rest on the same evidence.
3. **Eligible means** all three of these hold:
   - same epoch;
   - same fidelity as the round, per [Noise and replication policy](https://github.com/upadhyan/bo-autoresearch/issues/7);
   - every value inside the round's lever ranges, after the mapping rules below.

   Ineligible trials stay in the log as telemetry.

### Mapping rules
4. **A lever is added.** At registration, every lever must declare a **baseline**: the value at which its code path does exactly what the code did before, lying inside the lever's range. Old trials are seeded with the lever at its baseline. A lever with no such value makes old trials ineligible for any round that includes it.
5. **A lever leaves the search space.** What happens depends on why:
   - **Credibly irrelevant** (rejected `irrelevant`, or frozen because its own upper bound is below δ): keep all trials and drop the lever's key. Its effect is bounded by δ and just adds to the noise. The noise-homogeneity gate catches any unevenness.
   - **`no-improvement`, parked, or excluded by masking:** keep only trials where the lever sat at its baseline.
6. **A range is narrowed.** Trials outside the new range are dropped from both the sampler and the verdict GP. They are never clipped, because clipping records results at values that were never run. Keeping them would also skew samples toward the range edge (see the [Optuna research](https://github.com/upadhyan/bo-autoresearch/issues/2), fact 6). A widened range keeps every old trial.
7. **Hypotheses are merged.** The merge must declare an explicit mapping from old lever values to new ones, e.g. BN=on → `BN` in {none, BN, LN}. Trials the mapping can't express are ineligible.
8. **A hypothesis is revived.** The new version's eligible trials follow the normal rules: same epoch, same fidelity, in range.
9. **Masked levers.** Seeded trials carry the *sampled* values, consistent with [Hypothesis lifecycle](https://github.com/upadhyan/bo-autoresearch/issues/6).

### Code changes and epochs
10. **Every trial records the code version it ran on.**
11. **Equivalence check.** After any code change, the harness runs the incumbent and the baseline config, 2 replicates each, at the current fidelity on the new code.
    - If both agree with their logged means within 2σ, prior trials stay eligible.
    - Otherwise a **new epoch** starts: earlier trials become telemetry, σ is re-estimated, and burn-in restarts.

    New lever code at its baseline should pass trivially, so the check catches a baseline that isn't really a no-op.
12. **The user can declare a change breaking**, e.g. a new dataset. The harness then skips the check and starts a new epoch.

### Round 1
13. **Round 1 seeds** are the k=5 baseline replicates plus up to ~5 configs the user names in pre-loop grilling. The named configs are bounds-checked and run as agent-chosen trials, so they don't count toward range coverage or burn-in.
14. **Not accepted as seeds:**
    - **Historical results from outside the harness,** because their seed, fidelity and code version are unknown. They can inform hypothesis rationales as text only.
    - **Distributional priors (πBO),** because they fade out and distort the evidence the verdicts rest on (see the [constraint research](https://github.com/upadhyan/bo-autoresearch/issues/17)).

### Weighting
15. **No cap or age weighting in v1.** Every eligible trial goes in with equal weight. Epochs handle staleness, and burn-in counts only fresh sampler trials, so a large warm start can't rush a verdict. A cap can be added later if `GPSampler` fit time becomes a problem.

### Glossary
- Added **Baseline**, **Experiment log** and **Epoch**.
- **Warm start** now reads as eligible experiment-log trials rewritten into the round's space.
- Replaced "off" with baseline throughout.

### Knock-on for open tickets
- **Experiment log schema:** add a code version and epoch per trial; per-lever baselines; merge mappings; equivalence-check records and their outcome; epoch-start events, including user-declared breaking changes; and the provenance of user-named seed configs.
- **Code-change management:** lever code must have a true no-op at its baseline, and the harness verifies this by the equivalence check. Every trial must record the exact code version it ran.
- **Pre-loop grilling script:** collect up to ~5 named seed configs. Explain that historical results inform rationales only.
- **Runner harness API:** needs the eligibility function, the mapping rules above, bounds-checked seeding, and the equivalence check.
- **Agent roster and contracts:** registration requires a baseline for each lever, and a merge must declare its value mapping.
- **Round termination rule:** an equivalence-check failure ends the round and starts a new epoch.
