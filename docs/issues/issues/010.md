# Issue #10: Round termination rule

- State: CLOSED
- Author: upadhyan
- Created: 2026-09-25T02:57:01Z
- Labels: wayfinder:grilling


## Question

What ends a **round** and triggers analysis? Options are a fixed trial count, a plateau in the incumbent, a budget fraction, or a pre-registered reject condition becoming decidable.

What ends the whole research run? The rule lives in code, not agent judgment, since 2608.00316 leaves stopping to the agent's judgment. Replicates from **Noise and replication policy** consume this budget.

**upadhyan** (2026-09-25T03:05:17Z):

Constraint from [Research: tools for lever importance and interaction detection](https://github.com/upadhyan/bo-autoresearch/issues/3): a reject verdict needs at least `max(10·d, floor)` trials, where d is the number of active levers, plus coverage of each lever's range. Otherwise the verdict is "inconclusive". Round length has to be set against that bar, or rounds should end once enough evidence to decide has accumulated, since a round that is too short can never reject anything.

**upadhyan** (2026-09-28T21:10:54Z):

## Resolution

**Gist:** rounds and runs end on harness rules and hooks, never on the orchestrator's judgement.

A round ends when:
- the search space changes;
- the fidelity changes, or a new epoch starts;
- a stall or the round cap fires;
- or the user asks for it.

Rounds never end the run. The run ends only when the budget is spent, when the user stops it or their target is confirmed, or when the hypothesis list is **exhausted**.

Combinations between hypotheses are handled by LLM judgement that the pipeline *forces* to happen. Every removal of a hypothesis triggers an **interplay review**: a subagent is given the removed hypothesis's experimental data and asks whether anything still untested might interact with it.

### Verdict checks
1. **Spacing.** Each hypothesis gets its first verdict check at burn-in, after max(10·d, 20) fresh sampler trials. After that, it is checked every max(5·d, 10) fresh sampler trials. Each check after burn-in doubles as the confirming check for a pending reject. There is no per-trial checking, because frequent looks inflate false rejects.

### Round ends (all harness rules)
2. **The search space changes.** A confirmed reject, a freeze, a narrowing or a merge ends the round immediately.
   - Trials already running finish and are logged, and the next round takes them if they're eligible.
   - A retain does **not** end the round, because retained levers stay in the search.
   - A pending reject holds the round open until its confirming check.
3. **Fidelity changes, new epochs and broken proxies.** A fidelity change, a failed equivalence check (new epoch), or a proxy drift check that flags the proxy broken all end the round.
4. **Stall.** The round ends when all of these hold:
   - the incumbent hasn't improved by ≥ δ over the last max(5·d_total, 20) fresh sampler trials;
   - no reject confirmation is pending;
   - every active hypothesis has passed burn-in.
5. **Round cap.** A round may use at most ~25% of the remaining budget, so hypotheses in the queue always get a slot.
6. **User checkpoint.** In checkpoint mode, the run pauses at each round boundary, as already decided.
7. **Queued hypotheses join at round boundaries only.** Registered hypotheses wait in the queue and never interrupt a round. The round summary records which trigger ended the round.

### Stalled hypotheses
8. **Escalation.** A hypothesis whose gates keep failing is escalated mechanically:
   - After its first stalled round, the next round increases its replicate share. If calibration says the effect can't be resolved at the current rung, the next round moves up a fidelity rung instead.
   - Once it has used max(40·d, 80) fresh sampler trials without a verdict, the harness marks it **inconclusive** and frees its slot. This **amends** [Hypothesis lifecycle](https://github.com/upadhyan/bo-autoresearch/issues/6), where inconclusive was only assigned when the research ended.

### Combinations
9. **What already covers combinations:**
   - √V_T is a total-order index and Δ optimises the co-active levers, so "A helps only with B" is never rejected while A and B share a round.
   - Retained hypotheses stay active, so later hypotheses are always tested on top of them.
10. **Interplay review.** Whenever a hypothesis is **removed**, meaning rejected, made inconclusive or parked, the harness emits a removal event, and the pipeline spawns an interplay-review subagent.
    - **Input:** the removed hypothesis's verdict record, partial-dependence summaries, its interaction indices with every lever it was tested alongside, and the context it was tested in (the retained set and co-active hypotheses at the time). It also gets the **untested list**: registered, proposed, and not yet activated.
    - **Question:** "Is there anything in the untested list that might interact with this?"
    - **Output:** schema-checked. Each flagged pair comes with a reason that cites the evidence.
    - **Effect:** each flagged partner is linked. When the partner activates, the removed hypothesis is revived as a new version and scheduled into the **same round**. Each (removed hypothesis, partner) pair can be revived at most once.
11. **The hook forces the review.** A hook on the harness's verdict command injects the requirement to run the review. The `Stop` hook and the round-start `PreToolUse` hook both block (exit code 2) while any removal event has no interplay review recorded.
12. **The revival check at registration is kept.** It runs when a new hypothesis registers and looks in the other direction, flagging past rejects that might interact with the newcomer. Both checks can use the same subagent role.
13. **Scheduling.** When filling slots, hypotheses flagged as possibly interacting go into the same round where the dimension cap allows it.
14. **Keeping retained levers in the search.** When the dimension cap gets tight, the oldest retained hypotheses whose posterior is concentrated are narrowed, never frozen, so they stay in the search space as context.
15. The mechanical combination sweep was considered and **dropped** in favour of the forced interplay review.

### Budget
16. **Budget is compute time**: the summed wall-clock time of trials, set by the user before the loop. Calibration, baseline replicates, equivalence checks and replicates all count against it. About 5% is **held back** for the final confirmation of the incumbent at the reference fidelity. The user can also set a trial-count ceiling as a safety stop.
17. **The harness tracks budget, not a model.** The harness keeps a **budget ledger** in the experiment log, from each trial's measured wall-clock time. It refuses to start a trial whose estimated cost, taken from the calibrated rung's cost, would dip into the reserve. No agent keeps track of a timer.

### Run end
18. **The run ends only when:**
    - (i) the budget, minus the reserve, is spent;
    - (ii) the user stops it;
    - (iii) a target objective the user set is reached and confirmed;
    - (iv) **exhaustion**: the queue is empty, no active hypothesis is undecided, every removal event has its interplay review, every revival those reviews requested has run, and the orchestrator registers nothing new at the round boundary.
19. **No stall-based ending.** Stalled rounds and no-progress streaks never end the run. If the initial list has 80 hypotheses, all 80 get explored.
20. **Wrap-up.** At any run end, the reserve runs the final confirmation at the reference fidelity. Hypotheses still active become inconclusive. If (i)–(iii) ended the run before exhaustion, untested hypotheses are listed in the final deliverable.
21. **Hook enforcement:**
    - The `Stop` hook exits with code 2, blocking the orchestrator from stopping, unless the ledger shows (i), (iii) or (iv), or the user has stopped the run.
    - The `PreToolUse` hook on round start blocks a new round once the run has ended.

### Standing preference
Agent control goes in hooks and deterministic harness processes. The LLM makes the judgement calls, and hooks force them to happen. This is added to the map's Notes.

### Glossary
- Added **Interplay review**, **Verdict check** (because *checkpoint* is reserved for the user pause), **Stall** and **Budget**.
- **Revival** now covers any removed hypothesis being brought back because a possible partner is being tested.
- **Fidelity**'s avoid-note now reserves *budget* for compute time.

### Knock-on for open tickets
- **Experiment log schema:** add the budget ledger, round-end trigger records, removal events, interplay-review records with their flagged pairs, the test context of each reject, escalation state per hypothesis, and the run-end reason.
- **Agent roster and contracts:** add the interplay-review subagent (input bundle, output schema, evidence-citing reasons). It shares a role with the registration-time revival flagger.
- **Runner harness API:** add verdict-check scheduling, round-end triggers, the budget ledger with cost-aware trial refusal, the reserve, removal events and escalation.
- **Pre-loop grilling script:** collect the compute budget, an optional target objective, an optional trial-count ceiling, and confirm the ~5% reserve.
- **Final deliverable:** report the run-end reason, untested hypotheses, inconclusive-by-cap hypotheses, and revivals from interplay reviews with their outcomes.
- **Enforcement hooks** is now a ticket, seeded with the hooks decided here.
