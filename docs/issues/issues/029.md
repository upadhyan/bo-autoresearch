## What to build
Scheduling and run control:
- The harness fills slots from the registered queue by orchestrator-set priority, within a dimension cap derived from the budget.
- `prioritize`, `park`/`unpark` (with a reason, returning with the same version), and a flag to the user when a hypothesis is left unselected for N rounds.
- `enqueue` for agent-chosen trials, capped per round with a cap that shrinks each round, and an expected objective required.
- `record expected`: `round-run` is refused until every active hypothesis has an expected verdict.
- `checkpoint` and `stop`, and an optional target that must be reached and confirmed.
- The run ends only on budget, user stop or a confirmed target (exhaustion comes in ticket 09). Registered hypotheses join only at round boundaries.

## Acceptance criteria
- [ ] Slots follow priority and never exceed the dimension cap.
- [ ] Agent-chosen trials beyond the cap are refused, and `enqueue` without an expected objective is refused.
- [ ] `round-run` is refused while any expected verdict is missing.
- [ ] A reached target ends the run only once it's confirmed. A spent budget ends the run. A stop ends it.
- [ ] A parked hypothesis returns with the same version, and parking is never counted as evidence.
- [ ] Starvation is flagged after N rounds.
