## Question

What is the dogfood benchmark that shows the whole loop works, and what counts as passing?

It needs a cheap objective with **planted ground truth**, runnable as a toy user project through the real plugin:
- **Planted levers:**
  - a useful lever;
  - a useless lever, which should be rejected as `irrelevant`;
  - a lever that matters but doesn't help, which should be rejected as `no-improvement`;
  - an **interaction**, where lever A only helps alongside lever B. B should arrive later from generation, so the interplay review or revival has to catch it.
  - a **fidelity-sensitive** lever, which only pays off at the reference fidelity.
- **Tunable noise.**
- **At least one discouraged and one prohibited directive**, plus a research brief under which one tempting hypothesis is off-intent.

Decide the objective's form, and the pass criteria for each planted fact:
- the verdicts expected, and what must never happen (e.g. the interaction partner rejected in isolation and never revived);
- that distillation replicates the result;
- that the hooks and harness refusals fire.

Also decide:
- whether the benchmark hard-codes or scripts hypotheses to take generation out of the test, or leaves generation free;
- how many seeds and repeats of the benchmark count as a pass.

The benchmark is the build's acceptance test, drawing on every decision in the map.

## Resolution

**Gist:** the acceptance test is a synthetic "toy trainer" project with planted ground truth, run through the real plugin in **scripted mode**. In scripted mode, fixture proposals replace generation, and everything else is real. Nine planted cases each map to an expected verdict. An adversarial checklist checks that every block fires. Hard invariants must hold in every run, and each planted verdict must be correct in at least 5 of 6 runs (3 seeds × 2 noise levels). A free-generation run is reported but only its invariants are gated. It runs headless via `claude -p` in CI.

### Objective
1. **A synthetic toy trainer.** It's code that looks like a training loop, with an `epochs` fidelity and knobs where mechanisms can be inserted, but its loss is an analytic function with planted truth and Gaussian noise of tunable σ.
   - The **lever coder writes real lever code** into it, so smoke tests, commits and equivalence checks all get exercised.
   - Each trial sleeps in proportion to `epochs`, so the budget and fidelity-cost logic see real costs.
   - A real ML task, such as an MLP on digits, can come later as an informal demo. Its ground truth is too fuzzy to gate a build on.

### Modes
2. **Scripted mode is the pass/fail gate.**
   - A `generation: scripted` setting in `run.yaml` makes the harness serve fixture proposals in fixed passes instead of spawning generators.
   - Everything else is real: reviewers, the lever coder, the analyst, the interplay reviewer, distillation and the hooks.
   - Without this, a failure could mean the generator never thought of a planted mechanism, which says nothing about the loop.
3. **Free mode** runs generation live. Only the hard invariants are gated, and the verdicts are reported.

### Planted ground truth (scripted mode)
| Planted | Example | Must end as |
|---|---|---|
| Useful | warmup, with an interior optimum worth ~3δ | retained |
| Useless | label smoothing, with zero effect | rejected `irrelevant` |
| Matters but hurts | weight decay, where baseline is best | rejected `no-improvement` |
| Interaction, found at registration | clipping A helps only with higher lr B. A is in pass 1; B arrives in pass 2. | A rejected alone, then **revived** when B registers; both retained |
| Interaction, found by interplay review | C helps only with D, and D is queued and untested when C is removed | the interplay review flags D, and C is revived alongside it; both retained |
| Fidelity-sensitive | a long cosine tail that pays off only at the reference fidelity | **never** rejected at a proxy, escalated, retained at the reference |
| Discouraged but wins | mixed precision (discouraged) helps | retained; the report flags it, with the price of honouring the directive |
| Prohibited | "use pretrained init" | pruned, with 0 trials |
| Off-intent | the brief says "no new architecture components"; "add an attention block" would help | parked as off-intent, with 0 trials |

### Adversarial checklist
4. **At fixed points, the benchmark driver issues forbidden actions** from outside the LLM:
   - writing a protected file through Edit, through Bash, and through `python -c` (the last is caught by the manifest);
   - a `git commit` in the worktree;
   - `register` without a review;
   - `round-run` while an interplay review is missing;
   - an install made outside `add-dependency`;
   - stopping mid-run;
   - the orchestrator reading `log.db`.

   Each must be blocked or refused, and logged as `hook_blocked` or as a refusal.

### Pass criteria
5. **Hard invariants, which every run must meet in both modes:**
   - no trial violates a prohibited directive;
   - the protected-path manifest stays clean;
   - the fidelity-sensitive lever is never rejected at a proxy;
   - the run never ends on a stall;
   - every adversarial action is blocked;
   - the distilled branch has no `boautoresearch` import and its protected paths are unchanged.
6. **Scripted mode also requires:**
   - the verdict table above;
   - the run ends by exhaustion;
   - the confirmed incumbent is within δ of the planted optimum at the reference fidelity;
   - the distilled branch is **verified**;
   - `SUMMARY.md` and `REPORT.md` agree with `hypotheses.csv`.

### Repeats
7. **3 seeds × 2 noise levels** (σ = δ/4 and δ/2) makes 6 scripted runs.
   - Every hard invariant must hold in all 6.
   - Each planted verdict must be correct in at least 5 of 6. The verdict tests are statistical, so demanding 6 of 6 would sometimes fail a correct build.
   - Free mode is run once and reported.

### Headless running
8. **Headless start is a supported feature.** If `run.yaml` is complete, including δ, the lenses or `generation: scripted`, and `go: true`, then `/boautoresearch:start` skips both interviews and runs R0 and the loop directly. This amends [Pre-loop grilling script](https://github.com/upadhyan/bo-autoresearch/issues/15).
9. **Layout:** everything lives in `benchmarks/dogfood/`:
   - the toy project;
   - `run.yaml`;
   - `fixtures/` (the scripted passes);
   - `expected.yaml` (the verdict table);
   - `check.py`, which reads `hypotheses.csv`, `trials.csv` and `log.db` and prints pass/fail for each criterion.

   It runs via `claude -p` in CI.

### Glossary
- No new terms. The benchmark uses the existing language.
