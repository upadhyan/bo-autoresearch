## What to build
Pre-registered hypotheses and lever code written just in time:
- The hypothesis spec schema, covering: id `H<n>.v<k>`, a title of 80 characters or fewer, rationale, mechanism, provenance, lens, directive ids, and the fidelity-sensitive flag with its reason.
- Each lever has a kind: `float`/`int` (low, high, log), `categorical` (options), or `bool` (`why_not_graded` required). It also has a baseline inside its range, and a predicted direction for graded levers.
- `propose` and `register`. Registration freezes the spec.
- `lever()` reads the trial's resolved values, falling back to the committed `levers.json` (baselines) outside the harness.
- A static check refuses lever code that reads config other than through `lever()`.
- `commit-lever <H>` only after `smoke <H>` passes (one trial at baseline, one at a random in-range point, at the cheapest rung). One harness-made commit per hypothesis version, and each round is pinned to a commit.
- Refusal on a dirty worktree.

## Acceptance criteria
- [ ] Specs missing a baseline, with a baseline outside the range, missing a predicted direction on a graded lever, or with a `bool` lacking `why_not_graded` are refused.
- [ ] Lever code that reads config without `lever()` is refused.
- [ ] `commit-lever` is refused until `smoke` passes. After it, the commit SHA is logged against the hypothesis version.
- [ ] Every trial records the commit it ran on. Rounds refuse to start on a dirty worktree.
- [ ] At baseline, the toy's objective equals its value before the lever was added.
