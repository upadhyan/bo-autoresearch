## What to build
The orchestrator's loop instructions, and the five subagents as plugin agent definitions:
- **Hypothesis generator:** one per lens, run in parallel, at least 2 mechanisms per pass.
- **Lever coder:** sequential, `lever()` only, declares touched files, runs smoke then `commit-lever`.
- **Registration reviewer:** directive, intent and conflict verdicts. Read-only.
- **Interplay reviewer:** read-only.
- **Round analyst:** a cited narrative, diagnostics and suggestions. Read-only.

Each has its prompt, a tool restriction and a tier (top, meaning `opus` on Claude Code). Each ends with `record <kind>`. The orchestrator drives only the CLI and follows `next`. It runs `round-run` in the background, records expected verdicts, and never activates hypotheses. Use `/writing-for-agents` for the prompts.

## Acceptance criteria
- [ ] On a toy project in free mode, a headless run completes several rounds with no manual intervention.
- [ ] Every subagent's output lands through `record`.
- [ ] No read-only agent runs a non-allowlisted command, as confirmed by the `hook_blocked` log and the transcripts.
- [ ] The orchestrator never reads raw logs.
- [ ] Lens generators produce proposals from distinct mechanisms, and duplicates are caught by the reviewer.
