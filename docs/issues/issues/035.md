## What to build
`/boautoresearch:start`, the pre-loop grilling:
- Interview part 1, in order: objective (plus generating the runner, a baseline run outside the harness, and the deterministic question), research brief, directives (preferences rewritten as discouraged), protected paths, fidelity (reference plus ladder), budget (compute time, target, ceiling, `workers`, k, checkpoint mode), seeds and ideas, lenses.
- It writes a `run.yaml` draft, then runs `init` and R0.
- Interview part 2: show σ, the calibration results and R0's cost. Suggest δ = 2σ, with an estimate of the trials a verdict needs and an infeasibility warning. Fix δ for the run. Review the generated list once.
- The R1 gate as a harness refusal.
- Headless start when `run.yaml` is complete, including `go: true`.

## Acceptance criteria
- [ ] `round-run` for R1 is refused until every gate condition holds, each tested at Seam 1.
- [ ] Headless start from a complete `run.yaml` reaches R1 without prompting, driven via `claude -p` on a toy project.
- [ ] An interactive session (manually checked) asks the sections in order, with recommendations, and produces a `run.yaml` the user can edit.
- [ ] δ can't be changed after it's set.
