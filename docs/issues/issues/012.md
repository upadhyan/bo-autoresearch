# Issue #12: Code-change management

- State: CLOSED
- Author: upadhyan
- Created: 2026-09-25T02:57:05Z
- Labels: wayfinder:grilling


## Question

How does lever code enter the user's project?

Decide on a branch or worktree per research run versus per round, how each hypothesis's code is gated behind its levers so older trials stay reproducible, what happens to code once its hypothesis is rejected, and how the pre-loop grilling session marks code as untouchable.


---

**upadhyan** (2026-09-28T20:53:03Z):

Knock-on from [Warm-start policy](https://github.com/upadhyan/bo-autoresearch/issues/9): at its baseline, lever code must be a true no-op, i.e. reproduce the code's earlier behaviour exactly. The harness verifies this with an equivalence check (the incumbent and baseline, 2 replicates each, within 2σ) after every code change. A failure starts a new epoch. Every trial must record the exact code version it ran.

## Resolution

**Gist:** each research run gets its own branch in a dedicated git worktree, and its own dedicated venv. The harness commits each hypothesis version as one lever-gated commit. Code changes only between rounds. The code of a removed hypothesis stays in place, pinned at its baseline, until wrap-up builds a verified **distilled branch**. Hooks and the harness enforce **protected paths**, and nothing is ever merged into the user's branches.

### Branch and worktree
1. **One branch per research run**, `bo-research/<run-id>`, in a dedicated worktree. It is taken from the user's HEAD when the run starts, and the user's own checkout is never touched.
   - Branches per round were rejected, because the warm start needs every lever's code to exist together, each at its baseline.
2. **The run needs a clean start.** The harness refuses to start if the user's tree has uncommitted changes, since they would silently be missing from the worktree.

### Gating and reproducibility
3. **Levers are read only through the harness**, e.g. `lever("h7.warmup_frac")`. At its baseline value, the code runs the original path.
   - A static check at registration refuses lever code that reads config any other way.
4. **One harness-made commit per hypothesis version**, made at registration. Its SHA is the code version recorded on each trial.
   - Any old trial can be reproduced from its SHA plus its lever values.
   - HEAD at baseline reproduces it too, which the equivalence check from [Warm-start policy](https://github.com/upadhyan/bo-autoresearch/issues/9) verifies.

### When code may change
5. **Code changes only between rounds.**
   - Each round is pinned to one commit.
   - The harness refuses to start a round on a dirty worktree.
   - A `PreToolUse` hook blocks writes to the worktree while a round is running.
6. **Changes that aren't levers**, such as a refactor, a crash fix or a bug found in the user's code, go through `commit_change(reason)`.
   - Each is logged with its reason and followed by the equivalence check, so a failure starts a new epoch.
   - A crash fix that doesn't change what the levers mean stays in the same hypothesis version. One that does change their meaning is a new version.

### Environment
7. **Each run gets a dedicated venv.**
   - It is created at run start from an exact freeze of the project environment, plus the harness package. The user's environment is never modified.
   - All trials, including the baseline replicates, run in it, so σ is measured in the environment the run actually uses.
   - This amends [Claude Code plugin anatomy](https://github.com/upadhyan/bo-autoresearch/issues/4), which had the harness installing into the project environment.
8. **New dependencies are allowed**, through a harness `add_dependency` command.
   - The command installs into the run's venv, commits the updated lock or freeze file, and runs the equivalence check.
   - A `PreToolUse` hook blocks `pip`/`uv`/`conda` installs made any other way, or aimed at any other environment.

### Code for removed hypotheses
9. **Nothing is reverted during the run.** Code for rejected, inconclusive or parked hypotheses stays in place, with its levers pinned at baseline and outside the search space.
   - Reverting would itself be a code change needing an equivalence check, and revival would have to re-apply the code.
10. **A distilled branch is built at wrap-up.**
    - It is the research branch with the commits of every non-retained hypothesis reverted, and the incumbent's lever values set as the defaults.
    - The final confirmation, run from the budget reserve, happens on the distilled branch.
    - If that result is more than 2σ from the research branch's result, the report flags it and the research branch is delivered as the result instead.

### Protected paths
11. **Pre-loop grilling produces a list of protected-path globs.**
    - **Protected by default:** the objective and evaluation code, data loading and splits, the harness package, the experiment log and the generated runner. This stops the research from improving its score by changing how the score is measured.
    - **User additions:** the user can add any other paths.
    - **Changes to the list:** only at a checkpoint.
12. **Enforcement:**
    - A `PreToolUse` hook blocks writes to protected paths, including writes made through `Bash`.
    - The harness refuses any commit whose diff touches a protected path.

### Hand-back
13. **Nothing is merged into the user's branches.** The user gets the research branch and the distilled branch, and merging is their decision.

### Glossary
- Added **Protected path** and **Distilled branch**.

### Knock-on for open tickets
- **Experiment log schema:** add the commit SHA of each hypothesis version; `commit_change` records with their reasons; dependency-change records; the protected-path list and its revisions; the venv freeze at run start; and which branch the final confirmation ran on.
- **Runner harness API:** add the committing `register`, `commit_change`, `add_dependency`, `lever()`, the refusals for a dirty user tree or dirty worktree, pinning each round to a commit, creating the per-run worktree and venv, and building and verifying the distilled branch.
- **Enforcement hooks:** add the protected-path write block (Edit, Write and Bash), the worktree write block during a round, and the block on installs made outside the harness.
- **Pre-loop grilling script:** collect the protected paths (confirm the defaults, take additions), and require a clean tree.
- **Agent roster and contracts:** whoever writes lever code must read levers only through `lever()`, and must declare which files the change touches.
- **Final deliverable:** deliver the distilled branch plus the research branch, and flag any disagreement found on the distilled branch.
