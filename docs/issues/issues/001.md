# Issue #1: Map: BO-driven autoresearch plugin

- State: CLOSED
- Author: upadhyan
- Created: 2026-09-25T02:56:01Z
- Labels: wayfinder:map


## Destination

A buildable **spec** for the BO-autoresearch Claude Code plugin, meaning its skills, subagent contracts, runner-harness Python API, experiment-log schema and warm-start policy, with every decision locked so the build can be handed off to later sessions.

## Notes

- **Domain**: a Claude Code plugin with an orchestrator skill, subagents and hooks, plus a small Python package that generated runner scripts import. Both live in this repo. The agent proposes falsifiable **hypotheses** that expose **levers**, and Optuna BO does the searching within each **round**. Terms are defined in `CONTEXT.md`, so use its language.
- **Skills every session should consult**: `/grilling` and `/domain-modeling` (keep `CONTEXT.md` current). Use `/codebase-design` for harness-API tickets and `/writing-for-agents` for anything that shapes a SKILL.md or subagent prompt.
- **Tracker**: see `docs/agents/issue-tracker.md`.
- **Standing decisions from charting**:
  - The objective is generic, with ML training as the first-class example.
  - The agent writes lever code into the user's project on a reversible branch or worktree.
  - v1 runs on a single machine with SQLite-backed Optuna.
  - Between rounds the orchestrator continues autonomously by default and writes a round summary. An opt-in checkpoint mode pauses before each new round.
  - There is one objective plus optional constraints, and everything else is logged as telemetry.
- **Prior art already reviewed**: *Agentic BO through Surrogate-Augmented Autoresearch* (arXiv 2608.00316). It puts an agent in the inner loop, has no hypothesis layer, and makes no code changes. Ideas borrowed from it are noted in the relevant tickets.
- **Core intuition**: agents doing autoresearch are myopic. They reject ideas without considering interactions and evaluate without structure. Every decision should push toward pre-registered, scientific-method rigour.
- **Agent control is deterministic**: wherever possible, control over the agent lives in hooks and harness processes, never in a model keeping track of timers or remembering duties. The LLM makes judgement calls, and hooks force them to happen. The harness CLI is the primary enforcer, and its refusals work on any host. Hooks are thin adapters, specific to the host, that call harness checks and are used only where the harness can't see.

## Decisions so far
- [Research: prior art in agentic autoresearch and agent-driven BO](https://github.com/upadhyan/bo-autoresearch/issues/5): no prior system combines pre-registered falsification, BO over graded levers, and warm start. Worth borrowing: POPPER's e-value falsification (safe to check every round), metadata-only registration of reject conditions, and LLINBO's gating of trials the agent injects. Worth avoiding: greedy one-change keep/discard, and letting the agent edit the harness or interpret results after the fact.
- [Research: Claude Code plugin anatomy](https://github.com/upadhyan/bo-autoresearch/issues/4): plugin agents can each be pinned to a model and a tool set and run in parallel or in their own worktree, but can't carry their own hooks. Schema-checked verdicts need workflow `agent({schema})` calls or a `SubagentStop` validation hook. Enforcement lives in plugin `hooks/hooks.json`, where only exit code 2 blocks. The Optuna harness installs into the user's project environment.
- [Research: tools for lever importance and interaction detection](https://github.com/upadhyan/bo-autoresearch/issues/3): the only defensible machine-checkable reject is the total-order Sobol index (main effect plus all interactions) from a noise-aware GP, with a credible upper bound below τ and gates on trial count, range coverage and surrogate fit. If a gate fails, the verdict is "inconclusive", never "reject". Optuna's fANOVA, PED-ANOVA and MDI report no interactions and no uncertainty, so they are telemetry only.
- [Research: Optuna mechanics for changing search spaces](https://github.com/upadhyan/bo-autoresearch/issues/2): model-based samplers use prior trials only when their distributions match exactly, so the warm start is a fresh study per round (same SQLite file), seeded via `create_trial`/`add_trials` with trials rewritten to that round's exact lever distributions. The harness must bounds-check seeds itself and mark crashed trials failed on resume.
- [Research: encoding hard and soft research constraints](https://github.com/upadhyan/bo-autoresearch/issues/17): prohibited limits never reach BO (the hypothesis is pruned, or the option is excluded from the search space). Discouraged limits stay out of the objective and the sampler (lower priority, per-trial `compat:` telemetry, a discouraged winner reported as a tradeoff). A penalised objective or πBO would corrupt the Sobol reject statistic or fade out. Laundering is caught by mechanism, not name.
- [Hypothesis lifecycle](https://github.com/upadhyan/bo-autoresearch/issues/6): states proposed → registered → active → retained / rejected / inconclusive / parked, plus pruned. Only harness mechanics reject or retain, and verdicts are recomputed every round. Rejection is scoped, and a hypothesis is revived as a new version when a new hypothesis might interact with it. Narrowing and freezing are events. Conflicts are caught at registration: a shared config path forces a merge, exclusive mechanisms are merged into a categorical or masked, and competing explanations are linked as rivals.
- [Noise and replication policy](https://github.com/upadhyan/bo-autoresearch/issues/7): the harness owns every seed and replicate. Noise is estimated from baseline replicates, re-estimated each round, and anchors the verdict GP. At least ~10% of trials are replicates, and each new incumbent is confirmed. The agent proposes a fidelity ladder (the minimum meaningful experiment). The harness validates it against the reference fidelity (ρ ≥ 0.8, spread ≥ 3σ) and picks the rung with the lowest cost to a verdict. Fidelity-sensitive hypotheses are never rejected at a proxy fidelity. There is no performance pruning.
- [Reject-condition form](https://github.com/upadhyan/bo-autoresearch/issues/8): the harness applies one fixed reject form, not author-written conditions. It uses √V_T (do the levers matter?) and the improvement contrast Δ (do they help?), both against a user-set minimum meaningful effect δ in objective units, which replaces τ. Rejects wait for a burn-in of fresh sampler trials and must be confirmed by a second check. Authors pre-register a predicted direction, and a contradicted prediction only flags the verdict. Judges must quote the verdict record exactly, enforced by a hook.
- [Warm-start policy](https://github.com/upadhyan/bo-autoresearch/issues/9): the append-only experiment log is the source of truth. One eligibility function (same epoch, same fidelity, in range) seeds both the sampler and the verdict GP. Added levers are backfilled at their no-op baseline. Credibly irrelevant levers are dropped from old trials, and any other lever that leaves is filtered to its baseline. Narrowed ranges drop trials rather than clip them. An equivalence check after every code change decides whether a new epoch starts. Round 1 is seeded with the baseline replicates plus up to 5 configs the user names. There are no πBO priors and no imported history.
- [Round termination rule](https://github.com/upadhyan/bo-autoresearch/issues/10): only harness rules end a round: a change to the search space, fidelity or epoch, a stall, a cap of about 25% of the budget, or a user checkpoint. A pending reject holds the round open. Rounds never end the run. The run ends only when the compute budget is spent (tracked in a ledger), when the user stops it or their target is confirmed, or when the whole hypothesis list is exhausted. `Stop`/`PreToolUse` hooks enforce this. Every removed hypothesis triggers a forced interplay review against the untested list, and a flagged partner revives the hypothesis into the same round. A stuck hypothesis escalates to more replicates or a higher fidelity rung, then becomes inconclusive at an evidence cap.
- [Code-change management](https://github.com/upadhyan/bo-autoresearch/issues/12): each run gets one branch in its own worktree and a dedicated venv, and new dependencies go in through the harness. Each hypothesis version is one harness-made commit, and levers are read only via `lever()`. Code changes only between rounds, and every change passes an equivalence check. Code for removed hypotheses stays pinned at its baseline until wrap-up builds a verified distilled branch. Hooks and the harness enforce protected paths (objective, evaluation, data and harness by default). Nothing is merged for the user.
- [Directives: prohibited vs discouraged vs preferred](https://github.com/upadhyan/bo-autoresearch/issues/18): there are two tiers, and "preferred" wishes are written as discouraged directives. The registry is owned by the harness and protected. Prohibited limits prune a hypothesis or cut values out of its ranges, and are checked at registration, on every commit diff and before every trial. Discouraged limits only lower priority and set per-trial compat flags, and a winner that violates a discouraged directive is flagged, with the price of honouring it (as amended by Final deliverable). Revisions apply at round boundaries. Intent fit is judged against a research brief rather than being a tier: the reviewer rates a hypothesis fits, stretch (lower priority) or off-intent (parked), never pruned. Repeated calls on the same concern become directives proposed to the user.
- [Experiment log schema](https://github.com/upadhyan/bo-autoresearch/issues/11): an append-only SQLite events table, where each event records its actor, and all state is computed from it. The harness CLI is the only writer. Optuna's `studies.db` is a disposable cache. Trials are logged before they run and before Optuna is told the result, so crash resume is mechanical, and a `SessionStart` hook injects the harness status. Expected verdicts are required before each round. The harness writes round summaries and a short `SUMMARY.md` (working, not working, still testing, set aside, up next). Everything lives in a protected `.bo-research/<run-id>/` folder. It includes the full event catalogue.
- [Runner harness API](https://github.com/upadhyan/bo-autoresearch/issues/13): the plugin ships a Python package, `boautoresearch`, which is installed into the run venv. Runner scripts and lever code see six names: `lever`, `seed`, `fidelity`, `log`, `artifact_dir` and `run`. Outside the harness, `lever()` returns the committed defaults. Levers are declared in the hypothesis spec, never in code. Each trial is a subprocess. The JSON CLI splits into free probes and logged actions that require a rationale. `round-run` is the one deep command, and the harness, not the orchestrator, fills round slots. The harness is the primary enforcer, and hooks are thin host-specific adapters. A prototype is linked from the ticket.
- [Agent roster and contracts](https://github.com/upadhyan/bo-autoresearch/issues/14): there are six roles: the orchestrator skill, lensed parallel generators, a just-in-time lever coder that must pass a smoke test, a registration reviewer, an interplay reviewer and a round analyst. Every subagent ends with `boautoresearch record`, which the harness validates, and a `SubagentStop` hook requires that record before the subagent can finish. No workflows. Every role is on the top tier (`opus` on Claude Code), and tiers map to models per host. Agents run only at round boundaries. Exhaustion needs a final generation pass with no survivors. This amends the timing in Code-change management and the exhaustion rule in Round termination rule.
- [Pre-loop grilling script](https://github.com/upadhyan/bo-autoresearch/issues/15): `/boautoresearch:start` runs interview part 1 (objective, brief, directives, protected paths, fidelity, budget, seeds and ideas, lenses), writes a `run.yaml` that `init` validates, then runs an automatic calibration round (R0: smoke test, calibration, baseline replicates). Interview part 2 sets δ from σ, fixed for the run, then reviews the generated hypothesis list once, with "go" as the default. The harness refuses R1 until every precondition holds. Range priors were dropped.
- [Final deliverable](https://github.com/upadhyan/bo-autoresearch/issues/16): the budget covers only the research loop, so wrap-up is unbudgeted and the reserve is gone. The distilled branch is a clean re-implementation of the retained mechanisms: a spec written from the evidence, reviewed, implemented from the base commit with no `boautoresearch` dependency, then verified by harness replicates against the research incumbent (2 retries, otherwise marked unverified). The research branch stays configurable. A winner that violates a discouraged directive is flagged, with the price of honouring it taken from the log. It also defines the schemas for `trials.csv` and `hypotheses.csv` and the section order of `REPORT.md`.
- [Enforcement hooks](https://github.com/upadhyan/bo-autoresearch/issues/19): hooks are thin, fail-closed adapters to `boautoresearch check`, and stay inert without an active run. They cover writes and reads, Bash commands (including an allowlist for read-only agents, installs, and git commands that rewrite history), subagent records, `Stop` (allowed only when waiting on the user, during a background round, or after the run ends and wrap-up finishes) and context injection. A hash manifest of protected paths catches any Bash write the parser misses. Everything else is a harness refusal.
- [Dogfood benchmark](https://github.com/upadhyan/bo-autoresearch/issues/20): the acceptance test is a synthetic toy trainer with planted truth: useful, useless and harmful levers, two interaction pairs (one found at registration, one by interplay review), a fidelity-sensitive lever, and discouraged, prohibited and off-intent cases. It runs in scripted mode (fixture proposals, every other role real), with an adversarial checklist of forbidden actions. Hard invariants must hold in every run, and each verdict must be correct in at least 5 of 6 runs (3 seeds × 2 noise levels). Free generation is reported only. It runs headless via `claude -p`, which amends Pre-loop grilling script.

## Out of scope

- **Multi-objective / Pareto search**: v1 optimizes one objective plus constraints.
- **Changing the objective mid-research**: it breaks warm-start and reject-condition comparability, so a changed objective starts a new research run, which may seed from the old log.
- **Remote or cluster execution**: v1 is single-machine only.
- **Token or cost accounting**: not needed.
- **Multi-fidelity BO and heteroscedastic noise models**: v1 fixes one fidelity per round and assumes constant noise. If the noise assumption fails, the verdict is inconclusive. See [Noise and replication policy](https://github.com/upadhyan/bo-autoresearch/issues/7).














- **Agent hosts other than Claude Code (Codex, opencode, …)**: v1 targets Claude Code only. The harness does most of the enforcement, so supporting another host later means writing hook adapters, not a redesign. It also needs a map from each role's tier to that host's models. Opencode supports many providers, so its map must be configurable by the user, and the chosen model must handle the structured `record` output ([Agent roster and contracts](https://github.com/upadhyan/bo-autoresearch/issues/14)). See [Runner harness API](https://github.com/upadhyan/bo-autoresearch/issues/13).
